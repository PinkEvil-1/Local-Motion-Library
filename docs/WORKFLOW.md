# 工作流與驗收

目標：即使原站下架，仍可在本機瀏覽全部 331 筆資料、分類、關鍵字、提示詞與演示。Vue 3 + TypeScript + Vite 負責應用；原始 fx.js / fx.css 透過隔離 iframe 保存；GSAP 3.13.0 與 14 插件安裝在本地。

## Agent 分工

1. 主協調：需求、驗收、檔案責任、整合與交付。
2. 來源調查：公開資料清單、來源、依賴、缺漏及使用條件。
3. Vue 開發：搜尋、篩選、排序、詳情、提示詞複製與收藏。
4. 演示整合：保留原始動畫，隔離樣式及執行環境，控制載入與卸載。
5. 獨立驗證：從需求與快照出發驗收，提供重現步驟，不自行修改正式程式。

流程：需求與驗收 → 來源調查 → 資料快照 → UI 與演示整合 → 開發自測 → 獨立驗證 → 修正再驗 → 交付。角色可以分階段啟動；本次主協調同時負責演示整合，另有獨立來源、Vue 與驗證 Agent。

## 範圍與差異

保存 331 筆資料、9 元件、7 時機、9 情境、CSS/GSAP/Canvas 演示、自訂文字（固定效果除外）、大型預覽及 SVG 上傳演示。新增本地收藏與完整 JSON 匯出。

不執行原站追蹤與遠端投稿。來源及作者作品集連結由使用者主動開啟。系統字型取代 Google Fonts，字型效果可能有差異。預覽移出畫面即卸載 iframe，以銷毀計時器、事件與動畫；每個演示獨立，避免共享 CSS 與全域狀態衝突。

## 驗收

資料比對與建置是開發檢查；獨立驗證另外測試搜尋、篩選、收藏持久化、預覽與鍵盤操作、手機寬度及無外部請求。逐項 smoke check 載入所有演示並觀察錯誤，仍不等於全部互動與視覺一致性證明。證據保存在 docs/VERIFICATION.md 與 docs/demo-verification.json。

## 更新與復原

npm run snapshot:check 只比較來源。明確需要更新後執行 npm run snapshot:update，舊版保留在 source-snapshot/history/<時間>/。更新涵蓋來源快照、資料與原始演示；保留 Vue 介面及使用者收藏。移除項目、新分類或新依賴需人工審閱，之後重跑測試、建置與驗證。原站斷線不影響既有本地版本。
